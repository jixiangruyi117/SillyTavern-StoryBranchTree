# 剧情分支树（SillyTavern Story Branch Tree）

在**同一条单人聊天记录**中创建、查看和续写多条剧情路线。分支只保存分叉后的新增消息，共同前文由路线共享。

> [!IMPORTANT]
> 这是用户维护的 SillyTavern 第三方界面扩展，不属于 SillyTavern 官方项目，也不修改酒馆核心文件。

## 核心功能

- **从任意楼层分叉**：普通分支沿用该楼当前显示的回复；同一个分叉点可开多条路线，也可在子路线继续开分支。
- **把重说作为独立路线**：从当前显示的 AI 回复直接建立重说分支；历史楼层可用左右箭头切换回复，已有后续路线会随回复恢复。
- **在剧情树中管理路线**：全屏查看主线与嵌套分支，缩放、平移、定位当前路线、整理布局；查看路线末楼摘要，并为路线和分叉点添加名称、摘要或备注。
- **确认后再切换或删除**：创建、切换及删除路线都有确认步骤；删除分支时会一并删除其下级路线。
- **聊天列表只保留一条记录**：路线数据保存在当前聊天中，不会为每个分支创建新的聊天记录；可随酒馆聊天记录保存和导入。
- **本地运行**：不调用模型、不连接外部服务，也不需要服务端插件；仅支持单人角色聊天，不支持群聊。

## 安装

在 SillyTavern 的 **扩展 → 安装扩展** 中粘贴仓库地址：

```text
https://github.com/jixiangruyi117/SillyTavern-StoryBranchTree
```

安装后刷新页面。点击聊天输入框左侧的魔法棒，在菜单中选择 **剧情分支树**，即可打开全屏树状图。滚轮可缩放、拖动可平移；点击 **定位当前** 可将正在聊天的路线移到画布中央，**重置视图** 可看全图。点击路线名可确认切换分支；打开 **分支详情** 可编辑备注或确认删除路线。轻点终点楼层查看正文，触屏长按可拖动终点位置；鼠标可直接拖动。树图按分叉楼层和子路线占用空间递归排列；手动拖动的位置会保留，点击 **整理布局** 可清除手动位置并重新排版。在任意聊天消息旁点击 **分支** 并确认后创建路线。

## 数据和行为

分支图保存在当前聊天的 `chat_metadata.story_branch_tree` 中。酒馆聊天数组始终显示当前选中的一条线性路线，拓展在切换时从共享前文和分支后缀重建该数组。每条消息会在 `extra.story_branch_tree_message_id` 中获得一个拓展专属标识，用于在消息序号变化后定位分叉点。同一楼层的各个原生重说版本也保存这个标识，避免切换旧回复时被误判为删除楼层。

路线层级编号只用于显示，内部仍以稳定 ID 保存路线。普通分支在父路线编号后追加分叉楼层和点内序号，如 `1.6.1`；重说路线使用 `R` 标明回复楼层，如 `1.R4.1`。旧版自动生成的“分支 N”和“从……节点继续”名称在树上按节点类型重新显示，不改动聊天数据；手动改名后的路线保留自定义名称。普通分支从共享前文中的消息创建时，会挂到拥有该消息的路线段；从另一回复版本创建的普通分支仍留在对应版本的路线下。

分叉点和每条出路线的摘要都由用户填写，不会请求模型生成；下一楼还没有出现在路线中时，树上显示“该楼层还未出现 · 无摘要”。

普通“分支”使用当前消息的活动 swipe 版本，从该楼层之后继续；“重说分支”则以当前 AI 回复楼层为回复组，并将当前显示的重说回复复制为新路线的起始楼层。两条路线的 AI 回复处于同一楼层；回复组记录原路线的回复，出线标注新路线采用的回复。每个重说版本保存独立标识，后续在某个回复版本上再开普通分支时，树图将其分叉点与其他版本分开。旧聊天首次重新载入时会根据已保存的回复内容认回标识。原路线的活动回复和后续楼层不会改动，其余重说仍是候选回复，不会自动建分支。新路线的起始回复只有当前显示的内容，之后仍可在新路线内正常重说。

历史楼层的左右箭头使用酒馆原有外观，由拓展处理路线选择，不会让酒馆直接改写已有后续楼层。未游玩的回复先作为隐藏的待续路线保存；发送下一楼并确认后才显示在剧情树中。此时再切回原回复，会恢复原路线（包括原有的第 7～38 楼）。同一回复下有多条后续路线时，箭头优先恢复最近通过箭头使用的路线，其余路线仍可从剧情树选择。原生重说历史列表仍可从楼层计数器打开；其中的“Create Branch”会创建另一条聊天，应使用本拓展的箭头或分支入口维护单条聊天。

### 路线状态与渲染

每条路线的消息附加数据会随消息一起保存和恢复。MVU 保存在消息 `variables[swipe_id]` 中的状态会随路线消息保存；从重说创建路线时，会把所选回复的变量移动到新路线第一个回复的位置。切换路线前，拓展保存当前聊天级 `chat_metadata.variables`；进入另一条路线时恢复它自己的快照。旧路线若没有快照，会优先从该路线最后一楼的 MVU 消息变量推导，因此旧数据中缺少逐楼变量的聊天级状态无法完整还原。路线切换后会发送酒馆的“聊天已加载”事件，让依赖该事件的界面扩展重新渲染。

### 当前限制

- 仅支持单人角色聊天，不支持群聊和临时助手聊天。
- 删除路线中的消息可能破坏其它路线引用的公共前文。拓展会检测到缺失的消息并尝试恢复当前有效路线；要整理路线，请暂时不要从酒馆原生消息菜单删除共享消息。
- 修改公共前文会影响引用该消息的路线；此版本不提供“只修改当前分支”的历史消息编辑。
- 分支数据随聊天元数据增长。分支只保存后续增量，但长期、多路线聊天仍会增加单个聊天文件体积。
- 本版本仅隔离酒馆助手的 `chat_metadata.variables`；分支仍共用一个聊天 ID，第三方脚本只在聊天 ID 变化时重建的内存缓存、外部存储或 itemized prompt 状态仍可能由不同路线共用。
- 原生隐藏标记 `is_system` 和原生摘要 `extra.memory` 随各路线的消息保存；共同前文的标记由各路线共享。切换路线会重建当前聊天数组并发出酒馆的“聊天已加载”事件，使依赖该事件的界面拓展重新渲染。只按聊天 ID、楼层号或外部存储保存状态的第三方拓展仍不会自动按路线隔离，需要逐个适配。
- 酒馆原生重说继续处理最后一楼的新回复生成；历史箭头由本拓展接管，且只在已有的非空重说回复间循环。待续路线处于最后一楼时，已有来源回复可用箭头切换，走到来源回复末尾后向右可按酒馆原生方式生成新回复。通过酒馆输入框按钮或回车发送待续回复时会确认；第三方插件或斜杠命令绕过输入框直接插入消息时，拓展会在消息加入后保留分支，无法提前弹出确认。

## 开发

项目没有构建步骤，可直接作为酒馆第三方拓展目录安装。运行最小检查：

```sh
npm run check
```
